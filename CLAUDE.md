Статический лендинг PLATFORMANCE (системное ведение магазинов на Wildberries/Ozon).
Чистый HTML/CSS/JS без сборщика, хостится на GitHub Pages.

- Репозиторий: `alexblacklucky/PLATFORMANCE`
- Прод-ветка: `main`
- Основной домен: `https://platformance.ru` — куплен 2026-08-11 на reg.ru, DNS-зона на `ns1/ns2.reg.ru`: 4 A-записи `@` на IP GitHub Pages + CNAME `www` → `alexblacklucky.github.io`. Файл `CNAME` в корне репо. Старый Pages-адрес `https://alexblacklucky.github.io/PLATFORMANCE/` работает через 301-редирект

## Структура

- `index.html` — главная; заявка — встроенная CRM-форма Bitrix24 (`script[data-b24-form="inline/4/btnjoi"]` в `#audit .form-card`, слот `.b24-form-slot`, запасные контакты `.b24-fallback`). Старая нативная `.lead-form` — в `snippets/native-lead-form.html`, её логика в `app.js` жива, но неактивна
- `privacy.html` — политика конфиденциальности (152-ФЗ)
- `thank-you.html`, `404.html` — служебные страницы (app.js НЕ подключён)
- `assets/app.js` — меню, табы, модалки, валидация формы, cookie-баннер
- `assets/config.js` — `window.PLATFORMANCE_CONFIG={webhookUrl,thankYouPage}` + список `files=[...]` для динамической подгрузки `v2-*.css/js`
- `assets/styles.css` — базовые стили (синхронная загрузка, есть в `<head>`)
- `assets/v2-*.css`, `assets/v2-dom-*.js`, `assets/v2-patches*.js` — слой визуального рефайна "v2", подгружается **асинхронно** через `config.js` после первого рендера

### ⚠️ Важная архитектурная ловушка v2-слоя
`config.js` хранит явный список файлов для динамической подгрузки. **`assets/v2-dom-1-4.js` в этот список НЕ включён** — он мёртвый код, никогда не выполняется. Раньше казалось, что он отвечает за блок «Система», но реальная разметка этого блока — в `index.html` напрямую, а `v2-patches-more.js` дополняет её в рантайме (кольца, theme-классы). **Перед правкой любого визуального бага сначала проверяй, действительно ли файл, который собираешься редактировать, загружается** (сверяйся со списком `files` в `config.js`), иначе правки уйдут в никуда.

8. **Автопилот блока «Система»** (по выбору пользователя из предложенных идей интерактива):
   - Итоговая механика (2-я итерация по просьбе пользователя): **луч радара — источник истины**. JS ведёт луч через rAF (`SWEEP_PERIOD=20000`, полный оборот 20с), узлы стоят в кардинальных точках 0/90/180/270°, порядок в DOM совпадает с ходом луча по часовой. Узел активируется ровно в момент прохода луча (`Math.floor(apAngle/90)`), карточка деталей меняется синхронно. Полоска прогресса на активном узле = угловое расстояние до следующего узла, через CSS-переменную `--ap-progress` (scaleX).
   - Логика в `app.js`: `startSystemAutoplay/pauseSystemAutoplay/stopSystemAutoplay` + IntersectionObserver (работает только когда блок во вьюпорте, threshold .35). Hover по карте — луч замирает, уход курсора — продолжает с того же угла. Ручной клик по узлу — остановка навсегда + класс `is-user-controlled` на `.system-map`, луч плавно гаснет (opacity 0). `prefers-reduced-motion` отключает всё.
   - CSS-анимация `radarSpin` в `v2-0.css` осталась как fallback на случай, если JS не выполнится (JS отключает её через `sweepEl.style.animation='none'`), замедлена до тех же 20s.
   - ⚠️ При этом обнаружен и удалён **скрытый дублирующий автоплей в `v2-motion.js`** (интервал 4.3s, «кликал» по узлам и перезапускался после ручного клика — конфликтовал с новой логикой). В `v2-motion.js` оставлена только логика класса `is-page-scrolled`. Если появится странное двойное переключение узлов — искать второй таймер именно там.
   - Отложенные идеи интерактива (пользователь выбрал только автопилот): вспышка узла при проходе луча, частицы данных по линиям к ядру, hover-связи между узлами с микро-подписями влияния.
